# Small Glossary

| Term | Plain meaning |
| --- | --- |
| Repository (repo) | The folder of code, examples and instructions. |
| Mock / synthetic data | Made-up inputs used instead of customer information. |
| Backend | Server-side code; credentials stay here, not in a card or browser. |
| Endpoint | An address a program sends a request to. |
| Authentication | How a connection proves its identity. |
| Authorization | Which account, user, record and operation that identity may access. |
| OAuth | A permission-granting installation flow; not the only auth option. |
| Scope | A named permission, such as reading contacts. |
| Environment variable | A setting supplied to the program; some settings are secrets. |
| Smoke check | A short check of basic behavior, not complete verification. |
| Contract test | Checks that expected inputs, outputs and failures stay consistent. |
| CI | Checks run by GitHub when code changes; not a deployment. |
| Dry run | The documented non-writing mode; verify what that specific program actually does. |
| Developer test account | A separate HubSpot environment with its own trial/feature limits. |
| Cutover | Switching an existing integration or view to a replacement. |
| Production | Real users and business data, requiring separate review and operation. |

A mock success, dry-run label or AI instruction is not a permission boundary.
